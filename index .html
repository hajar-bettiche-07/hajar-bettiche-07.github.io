Azure Zero Trust Network Access Lab

Securing remote administration of an Azure VM with Zero Trust principles.

Only WireGuard is exposed to the internet. SSH is dropped at the Azure NSG and reachable only from inside the VPN tunnel, so nothing answers on port 22 from the open internet. The Azure layer is provisioned with Terraform, and the Linux hardening was done by hand to understand how cloud and host controls interact.

  • Azure (Terraform): VNet, subnet, NSG, public IP and Ubuntu 22.04 VM. The NSG allows only UDP 51820 and denies all other inbound traffic.
  • WireGuard: server on 10.8.0.1/24, client pinned by AllowedIPs, peers keyed by public key, private keys locked down with chmod 600.
  • Host hardening: UFW allows SSH only from the VPN subnet, sshd uses key-only authentication with root login disabled, Fail2Ban protects the sshd jail.
  • Validated: SSH to the public IP times out, SSH through the tunnel works.
  • Troubleshooting documented: lockout after an ISP IP change (recovered through the Azure Serial Console, then redesigned so no public-IP rule can drift), Fail2Ban banning my own session, WireGuard not persisting after reboot, an Azure for Students region policy blocking the deployment.

Stack: Azure, Terraform, WireGuard, UFW, Fail2Ban, OpenSSH, Ubuntu 22.04

Private Virtualized Cloud with Proxmox VE

A segmented private cloud with isolated dev and prod environments.

Proxmox VE runs nested inside VirtualBox. Dev and prod live on separate virtual networks, and a dedicated controller VM is the only machine connected to all three networks, acting as bastion, Ansible controller and NAT gateway.

  • Provisioning: a Debian 12 cloud image turned into a template, then linked clones configured with cloud-init (hostname, static IP, SSH key).
  • Network: three Linux bridges, nftables on the controller with a default drop policy and NAT masquerade, and no rule between dev and prod. Isolation tested at network and service level.
  • Automation: Ansible playbooks (base packages, Docker and Compose, service deployment) with one inventory per environment. Workflow: test on dev, then apply to prod. Idempotence verified.
  • Services: nginx deployed with Docker Compose on both environments.
  • Lifecycle: snapshot and rollback tested, vzdump backup of prod and restore to a new VM.
  • Troubleshooting documented: nested virtualization blocked by Hyper-V, unstable ISO install (switched to cloud-init), no DHCP, SSH host key changes, RAM pressure.

Stack: Proxmox VE, KVM/QEMU, cloud-init, Ansible, Docker Compose, nftables, Debian 12

ChatBook: RAG Question-Answering on Books

Team project.

I contributed to ChatBook, an assistant that answers questions about a novel using only real passages from the text, to reduce LLM hallucinations. Books come from a Gutenberg dataset on Hugging Face, read in streaming mode. Paragraphs are converted to 384-dimension vectors with FastEmbed (BGE-small-en-v1.5) and stored in Qdrant, with one collection per book. For each question, the most similar passages are retrieved by cosine similarity (top-k) and sent to GPT-5-nano with strict instructions to answer from that context. A Gradio interface lets the user pick a book and chat.

Stack: Python, FastEmbed, Qdrant, GPT-5-nano, Gradio, Hugging Face
